# Raspison

Приложение группы М41О25 (РАНХиГС, Оренбург): расписание с распознаванием скана, домашка, новости, задачи, опросы, контакты, дни рождения, анонимные вопросы. PWA — ставится на экран «Домой» iPhone, расписание работает офлайн.

Документы планирования: `docs/PLAN.md` (архитектура, роадмап), `docs/BRIEF.md` (решения), `docs/QUESTIONS.md`.

## Стек

Next.js 16 (App Router) · Tailwind 4 · Motion · Drizzle + Postgres (Neon) · Cloudflare R2 (файлы) · PolzaAI (vision-модель для скана) · Serwist (service worker) · Vercel.

## Локальный запуск

```bash
npm install
cp .env.example .env.local        # DATABASE_URL на локальный Postgres, OCR_MOCK=1
npm run db:migrate                # применить миграции
npm run db:seed -- --demo         # группа + админ + 20 тестовых студентов + расписание
npm run dev                       # http://localhost:3000
```

Вход: код `M41-2025` → «Батутин Максим» → придумать PIN. Иконки PWA: `npm run icons`.

Проверки: `npm run typecheck && npm run lint && npm run db:check && npm test` (unit-тесты чистой логики) и `npm run build`. Экраны на iPhone-вьюпорте: `npm run e2e` против запущенного сервера (`BASE`, по умолчанию `http://localhost:3000`) — скриншоты в `OUT` (по умолчанию `e2e/shots`), сценарии в `e2e/*.mjs`; `npm run e2e:offline` — только против production-сборки на `:3001`. То же самое на каждый push делает GitHub Actions (`.github/workflows/ci.yml`).

## Развёртывание (один раз, ~40 минут)

Проект на Vercel уже создан (`raspison`, привязан к этому репозиторию: каждый push собирает деплой, защита превью-ссылок отключена — у приложения свой вход). Осталось дать ему базу, хранилище и секреты.

1. **Neon** (neon.tech, free, регион Frankfurt — рядом с `fra1` из `vercel.json`) → создать проект → скопировать строку подключения **с `-pooler`** → `DATABASE_URL`.
2. **Cloudflare R2** (free 10 ГБ) → создать бакет `raspison` → API-токен с правами Object Read & Write → `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`. Без этих переменных на Vercel загрузка файлов (фото к домашке, скан расписания, вложения помощника) отвечает понятной ошибкой «хранилище не подключено», а ночной cron каждый день краснеет: бэкап складывать некуда, и в «Диагностике» и у сторожа это считается провалом, а не пропуском. Всё остальное работает.
3. **PolzaAI** (polza.ai) → пополнить на 100 ₽ → ключ → `POLZA_API_KEY`. Модели: `OCR_MODEL=google/gemini-3.5-flash`, `OCR_MODEL_STRONG=anthropic/claude-sonnet-5` (проверь актуальные id в каталоге polza.ai/models). Не задавать `OCR_MOCK` в проде.
4. **Секреты**: `AUTH_SECRET`, `ANON_PEPPER`, `CRON_SECRET` — `openssl rand -base64 32` для каждого.
5. **Vercel → Settings → Environment Variables.** Только для **Production**: `DATABASE_URL`, `AUTH_SECRET`, `ANON_PEPPER`, `CRON_SECRET`, `POLZA_API_KEY`, `OCR_MODEL`, `OCR_MODEL_STRONG`, `R2_*`, `VAPID_*` (см. таблицу ниже). Для Production **и** Preview: `APP_TZ` и `NEXT_PUBLIC_APP_TZ` (= `Asia/Yekaterinburg`), `NEXT_PUBLIC_APP_ORIGIN` (= `https://raspison.vercel.app`, одинаково в обоих: на preview-адресе приложение покажет плашку «это тестовая копия» и уведёт на рабочий домен — ставить PWA на телефон можно только с него). В Preview базы и секретов намеренно нет: ветка не может ни прочитать, ни сломать боевые данные, а сборка без `DATABASE_URL` проходит. Плюс на первый запуск: `SEED_ADMIN_NAME="Фамилия Имя"` и `SEED_INVITE_CODE=M41-XXXX-XXXX` (без него код сгенерируется случайно и будет виден только в логе сборки); после первого входа обе удалить. Миграции применяет production-сборка; preview-сборки базу не трогают, если только не задан `MIGRATE_ON_BUILD=1`. Сборка сама откажется выкатываться, если в production нет `DATABASE_URL` или секретов, если задана только часть `VAPID_*` или ключи VAPID не принимаются `web-push`.
6. **Deployments → последний деплой → Redeploy.** Сборка на Vercel применяет миграции к базе из `DATABASE_URL` (production всегда, preview только с `MIGRATE_ON_BUILD=1`) и при заданном `SEED_ADMIN_NAME` создаёт группу и админа (повторные сборки ничего не дублируют). После первого входа `SEED_*` можно удалить.
7. **Первый вход**: открыть `/enter`, ввести код, выбрать себя, задать PIN → Профиль → Админка.
8. **Наполнение** (Админка): Люди → «Списком» — вставить список из беседы (по человеку в строке, нумерация и ДР через « — » допускаются), предпросмотр покажет, кто добавится (галочки на строках — заводим только отмеченные) и кто лежит в архиве; Предметы — справочник с преподавателями и аудиториями; Семестры — даты семестра и сессии; Настройки — время пар и инвайт-код; Расписание → Новая неделя → «По скану» или вручную → Опубликовать.
9. Кинуть в беседу группы ссылку и инвайт-код. Домен оставить `*.vercel.app` (кастомные домены Vercel из РФ блокируются РКН по IP).

Production-ветка проекта — `main`: push в неё собирает и выкатывает `raspison.vercel.app` (миграции применяются автоматически). Рабочие ветки `claude/*` собираются в preview (адрес вида `raspison-git-<ветка>-<команда>.vercel.app`) без базы — это только проверка сборки, а в production код попадает fast-forward-мержем в `main` после зелёного CI. Promote to Production из списка деплоев не подходит: он переиспользует preview-сборку, а миграции применяются только в production-сборке (`scripts/build.mjs`), поэтому после Promote код будет новее базы. Правила для разработки — в `CLAUDE.md`, действия при сбое — в `docs/RUNBOOK.md`, проверка на телефоне — в `docs/DEVICE-CHECKLIST.md`, порядок запуска на группу — в `docs/LAUNCH.md`. Cron из `vercel.json` (23:00 UTC = 04:00 по Оренбургу) подхватывается автоматически; Vercel сам передаёт `CRON_SECRET` в заголовке `Authorization`.

## Переменные окружения

Единственный читатель `process.env` — `lib/env.ts` (плюс `NEXT_PUBLIC_*` на клиенте и `VERCEL*` в сборке). Без необязательных переменных соответствующая часть просто выключена с понятным текстом в интерфейсе.

| Переменная | Обязательна | Без неё |
|---|---|---|
| `DATABASE_URL` | да (production — проверяет сборка) | ничего не работает; preview без неё собирается и живёт без данных |
| `AUTH_SECRET`, `ANON_PEPPER`, `CRON_SECRET` | да там, где есть база | подписи cookie и ссылок на файлы, анонимность вопросов, доступ cron |
| `APP_TZ`, `NEXT_PUBLIC_APP_TZ` | нет (умолчание `Asia/Yekaterinburg`) | — |
| `NEXT_PUBLIC_APP_ORIGIN` | нет | плашка «это тестовая копия» на чужом адресе выключена |
| `POLZA_API_KEY`, `POLZA_BASE_URL`, `OCR_MODEL`, `OCR_MODEL_STRONG`, `OCR_MOCK` | нет | распознавание скана и помощник по учёбе не отвечают; `OCR_MOCK=1` — тестовые ответы без ключа (CI, локально) |
| `ASSISTANT_MODEL`, `ASSISTANT_MODEL_STRONG`, `ASSISTANT_USD_RUB`, `ASSISTANT_POLZA_MARKUP` | нет | умолчания из `lib/env.ts`; курс и наценка влияют только на себестоимость в админке (`docs/AI-CHAT.md`) |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | нет | файлы и бэкапы выключены; cron ежедневно красный |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | нет (все три или ни одной) | пуши выключены, тумблер в Профиле объясняет почему |
| `HEALTHCHECK_URL` | нет | о пропавшем ночном cron никто не узнает письмом — только по «Диагностике» |
| `SEED_ADMIN_NAME`, `SEED_INVITE_CODE`, `SEED_GROUP_NAME` | только первый запуск | группа и админ не создаются сборкой (`SEED_GROUP_NAME` — шифр группы, по умолчанию `М41О25`: так приложение заводится для другой группы) |
| `MIGRATE_ON_BUILD` | нет | preview-сборка не трогает базу |
| `BOT_API_KEY` | нет | бот для MAX (`max-bot/`) не получает предметы группы для профиля; ключ тот же, что `RASPISON_BOT_KEY` у бота |

## Еженедельный ритуал (суббота, 10 минут)

Админка → Новая неделя (дата и чётность уже подставлены) → «По скану» → 1–3 фото скана → Распознать → проверить подсвеченные ячейки → Применить → при необходимости поправить тапом → Опубликовать. Замены в день занятий — тап по паре в редакторе опубликованной недели.

## Пуш-уведомления

Web Push (VAPID): новая домашка и перенос её дедлайна, расписание (отмена и возврат пары, замена в опубликованной неделе, публикация новой недели), новости, анонимные вопросы и ответы на них, новые опросы. У домашки будят только эти два повода — смена предмета, правка текста, дополнения и комментарии молчат, как и перенос дедлайна на уже прошедшую дату; отдельных переменных окружения ей не нужно, ключи те же. Включается в Профиле тумблером «Уведомления», там же галочки «что присылать» (общие для всех устройств человека). На iPhone это работает **только** в приложении, добавленном на экран «Домой», и только с iOS 16.4 — в Safari-вкладке тумблер не даст включить и объяснит, что сначала надо установить. Разрешение спрашивается по тапу, само не всплывает.

Ключи (один раз): `npx web-push generate-vapid-keys` → в Vercel → Environment Variables (Production): `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`mailto:` с почтой админа). Без ключей уведомления просто выключены, всё остальное работает; половинчатая настройка или пара ключей из разных генераций валит сборку с понятным текстом. **Ключи не менять**: при смене отваливаются все подписки, включать придётся каждому заново. Здоровье подписок (сколько, у скольких сбои) — строкой в «Диагностике».

Мёртвые подписки (404/410 от Apple или Google — удалили приложение, сбросили разрешение) удаляются при первой же неудачной отправке; те, что стабильно отвечают ошибкой, чистит ночной cron. Отправка идёт после ответа сервера (`after()`): упавшая рассылка не мешает создать новость.

## Бэкапы

Ежедневно cron складывает `backups/YYYY-MM-DD.json.gz` в R2 (храним 30); дамп снимается одной транзакцией, так что записи и их дополнения в нём согласованы. Восстановление в пустую базу: `npm run db:migrate && npm run db:restore -- ./2026-09-02.json.gz` (подробно и с шагами в Vercel — `docs/RUNBOOK.md`, раздел 5). Файлы-вложения не бэкапятся. Состав дампа — `lib/backup-tables.ts`: в него не попадают PIN-хеши, сессии устройств, попытки входа, квоты (анонимных вопросов и помощника), журналы ошибок и cron; подписки на пуши — попадают. После восстановления все входят заново по инвайт-коду и задают PIN. Полнота списка таблиц проверяется unit-тестом против схемы, а само восстановление репетируется в CI на каждом push: cron кладёт дамп в локальное хранилище, скрипт восстанавливает его во вторую базу.

## Защита входа

Инвайт-код — формат `М41-XXXX-XXXX` (~40 бит), меняется кнопкой в настройках; cookie «код проверен» подписана с привязкой к текущему коду и живёт 15 минут, так что смена кода обесценивает и её. PIN: после 5 неверных попыток подряд профиль блокируется на 1 минуту, затем 5, 30 минут и сутки (счётчик считается атомарно в базе — параллельные попытки его не обходят), текст ошибки называет срок; смена PIN в Профиле подчиняется той же блокировке; по IP — не больше 60 попыток за 10 минут (группа за одним NAT вуза). Свой PIN админ сбросить не может (чтобы профиль админа нельзя было занять) — если забыл, сбрасывает второй админ или напрямую в базе: `update users set pin_hash = null where id = '…'`. Сессия устройства живёт год, cron чистит отозванные.

## Роли

- **Админ** — всё: расписание, люди, предметы, отметки «кто сдал», удаление чего угодно.
- **Староста (модератор)** — новости, задачи, контакты, ответы на анонимные вопросы, закрытие опросов.
- **Студент** — ДЗ (создание, дополнение блоком, комментарии, «дубль»), опросы, реакции, анонимные вопросы. Лимит: 15 создающих действий в час.
