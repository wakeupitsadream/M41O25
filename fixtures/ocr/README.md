# Фикстуры распознавания расписания

Папка для реальных сканов и ожидаемых пар, по которым `npm run ocr:eval` считает качество распознавания
(precision/recall по ключу «день, пара, предмет»), латентность и число попыток. Сами файлы в репозиторий
не попадают (`.gitignore`: всё в `fixtures/ocr/*`, кроме этого README) — скан расписания внутренний документ вуза,
а репозиторий публичный.

## Состав фикстуры

- `<name>.jpg` (или `.jpeg`, `.png`, `.webp`) — фото или скан. Если документ снят в несколько кадров, нумеруй части:
  `<name>.1.jpg`, `<name>.2.jpg` — они уйдут в модель вместе, в порядке номера (как в приложении).
- `<name>.expected.json` — что на этом скане стоит у нашей группы.

Пример: `sat-2026-09-05.1.jpg`, `sat-2026-09-05.2.jpg`, `sat-2026-09-05.expected.json`.

## Формат `expected.json`

```json
{
  "group": "М41О25",
  "weekType": "upper",
  "synonyms": { "Матан": "Математический анализ", "Англ. яз.": "Английский язык" },
  "slotTimes": [{ "slot": 1, "start": "08:30", "end": "10:00" }],
  "lessons": [
    { "day": "mon", "slot": 1, "subject": "Математический анализ" },
    { "day": "mon", "slot": 2, "subject": "Английский язык", "weekType": "upper" },
    { "day": "tue", "slot": 3, "subject": "История России", "weekType": "both" }
  ]
}
```

- `group` — как группа подписана в шапке (по умолчанию `М41О25`); передаётся модели.
- `weekType` — чётность недели скана: `"upper"`, `"lower"` или `null`. Пары другой чётности из ответа модели
  и из `lessons` не считаются — так же поступает приложение.
- `synonyms` — необязательно: сокращения, которые считать тем же предметом. Сравнение и без них нечувствительно
  к регистру, «ё» и пунктуации, но «Матан» ≠ «Математический анализ», пока не сказано обратное.
  Пиши в `subject` то, что напечатано на скане, тогда синонимы почти не нужны.
- `slotTimes` — необязательно: сетка звонков, если она отличается от стандартной (нужна, когда модель
  вернула `slot: 0` и время).
- `lessons[]` — каждая пара группы на неделе: `day` из `mon..sun`, `slot` 1–10, `subject` — название как в ячейке,
  `weekType` по умолчанию `"both"`. Подгруппы в одной паре — две записи с одинаковыми `day` и `slot`.
  Преподаватели и аудитории в ожидание не пишем: метрика их не учитывает, а фамилии в файлах лишние.

## Как снимать фикстуры

Так же, как в субботу для приложения: столбец группы и шапка с днями и временем во весь кадр, без бликов и перекоса,
телефон параллельно листу. Полезный набор — три разных недели: обычная, с потоком (ячейка объединена на несколько
групп) и с рукописной правкой поверх зачёркнутого. Для каждой заполняй `expected.json` по бумаге, а не по ответу
модели, иначе метрика ничего не измеряет.

## Запуск

```bash
npm run ocr:eval                # основная модель, ключ Polza из .env.local; OCR_MOCK не должен быть 1
npm run ocr:eval -- --strong    # сильная модель
npm run ocr:eval -- --verbose   # печатать все пропущенные и лишние пары
npm run ocr:eval -- --mock      # без Polza: тестовый ответ; без фикстур — встроенный пример (проверка скрипта)
```

Каждый прогон без `--mock` стоит реальных рублей (2–8 ₽ за фикстуру, см. `docs/PLAN.md`) и не попадает в лимит
распознаваний приложения — не гоняй в цикле.
