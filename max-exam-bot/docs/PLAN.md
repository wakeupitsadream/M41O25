# План: учебный ассистент в MAX («билеты и задачи»)

Версия 1 от 03.09.2026. Рабочее название проекта — `max-exam-bot`, продуктовое имя выберем позже (нейтральное, без слова «списывание» — см. раздел 9).

## 0. Что решено на этапе вопросов

| Вопрос | Решение |
|---|---|
| LLM | PolzaAI (OpenAI-совместимый API, оплата в рублях, есть vision и embeddings) |
| Хостинг | Демо на Vercel Hobby; платная версия — Vercel Pro или Timeweb VPS. Код пишется hosting-agnostic |
| Аудитория | Открытый бот, продукт для студентов |
| Монетизация | Free (5 запросов/день) + один платный тариф ~199 ₽/мес |
| Предметы | Пресеты в репо (`config/subjects.json`, правятся раз в полгода) + пользовательские предметы в боте |
| RAG | Personal RAG: каждый пользователь загружает свои конспекты, база изолирована по пользователю |
| MAX | Бизнес-профиль ИП верифицирован, токен бота доступен |

## 1. Три жёстких ограничения, которые определяют архитектуру

1. **Vercel Hobby запрещает коммерческое использование.** Приём платежей на Hobby — нарушение Fair Use, проект могут снести. Поэтому: этапы 1–3 (без платежей) живут на Vercel Hobby, этап 4 (платежи) запускается только после переезда на Vercel Pro ($20/мес, зарубежная карта) или Timeweb VPS (~500 ₽/мес, российская карта). Рекомендация — Timeweb: дешевле, оплата из РФ, нет лимитов на время выполнения. Код с первого дня строится так, чтобы переезд занял час: один HTTP-обработчик webhook, Postgres как единственное хранилище, Docker-образ в репо.
2. **Webhook MAX должен отвечать быстро, а LLM думает 10–60 секунд.** MAX шлёт события повторно, если не получил быстрый 200 — на этом ловят дубли ответов. Поэтому обработчик: проверил секрет → записал `update_id` в таблицу дедупликации → вернул 200 → продолжил работу в фоне (`waitUntil` на Vercel, обычный async-таск на VPS). Fluid compute на Hobby даёт 300 с на функцию — хватает с запасом.
3. **Лимит сообщения в MAX — 4000 символов.** Развёрнутый ответ на билет легко больше. Поэтому ответ форматируется в markdown, режется по секциям (не по символам) и уходит серией из 1–3 сообщений, длинные секции прячутся за inline-кнопкой «Подробнее».

## 2. Стек

Язык — **TypeScript (Node 20)**, фреймворк **Hono**. Причина: один и тот же код без изменений работает как Vercel-функция и как обычный Node-процесс в Docker на VPS; на Vercel фоновая работа после ответа (`waitUntil`) доступна именно из Node-рантайма. Python на Vercel хуже поддерживает фоновые задачи, а код пишет Claude Code, так что язык для тебя нейтрален.

| Слой | Выбор | Почему |
|---|---|---|
| БД + векторы | Postgres + pgvector (на этапе демо — Supabase Free, потом тот же Postgres в Docker на VPS) | Одна база на всё: пользователи, лимиты, подписки, чанки конспектов, дедупликация. Переезд — `pg_dump` |
| ORM | Drizzle | Миграции в репо, типизация |
| LLM | PolzaAI, эндпоинт `https://polza.ai/api/v1`, SDK `openai` | Совместимость; смена модели — одна строка в конфиге |
| Embeddings | `text-embedding-3-large` через PolzaAI (проверить наличие `-small`, он в ~6 раз дешевле) | Тот же ключ |
| Парсинг файлов | `pdf-parse` (PDF), `mammoth` (DOCX), `xlsx` (таблицы), изображения — напрямую в vision-модель; сканы PDF без текстового слоя — постранично как картинки в vision | Без внешних OCR-сервисов |
| Хранение файлов | Не храним оригиналы. Файл → текст → чанки → embeddings в pgvector | Не нужен blob-storage, меньше ПДн |
| Платежи | ЮKassa (карты 2.8%, СБП от 0.4%, рекуррентные платежи, «Чеки от ЮKassa» под 54-ФЗ без своей кассы) | Работает с ИП, чеки закрывает сама |
| Крон | Vercel Cron (на Hobby — только ежедневный) / `node-cron` на VPS | Напоминания об окончании подписки, сброс дневных лимитов |
| Логи/ошибки | Вывод в stdout + таблица `events` в БД для аналитики | Без Sentry на старте |

## 4. Логика бота (как это выглядит для студента)

1. `/start` — короткое приветствие, три кнопки: «Задать вопрос», «Выбрать предмет», «Загрузить конспект». Первое сообщение сразу принимает вопрос, без обязательного выбора предмета.
2. **Вход**: текст, фото (одно или несколько), файл (PDF/DOCX/XLSX/TXT/изображение). Голос — не в первой версии.
3. **Классификация** (дешёвая модель, один вызов): `ticket` (теоретический вопрос/билет), `task` (задача с решением), `material` (пользователь прислал конспект для загрузки), `multi` (на фото несколько вопросов), `other`. Если предмет не выбран — та же модель угадывает его из списка предметов пользователя, при уверенности <0.7 бот спрашивает кнопками.
4. **Ответ на билет**, структура фиксированная: «Устно за 30 секунд» (3–5 предложений, чтобы прочитать шёпотом) → «План ответа» (нумерованные пункты с раскрытием) → «Термины и определения» → «Если преподаватель спросит дальше» (2–3 вероятных доп. вопроса с ответами). При наличии загруженных конспектов по предмету — ответ строится из них с пометкой «по твоему конспекту».
5. **Ответ на задачу**: «Ответ» (первым, одной строкой) → «Решение по шагам» → «Формулы/обоснование» → «Проверка». Для расчётных задач модель просят пересчитать результат перед выдачей.
6. **Multi**: бот перечисляет найденные вопросы и предлагает кнопками «Ответить на все» / выбрать номер.
7. **Материал**: файл парсится, режется на чанки, индексируется под `(user_id, subject_id)`. Бот отвечает: «Загружено: 42 страницы, предмет — Экономическая теория. Теперь отвечаю с опорой на конспект». Команда `/materials` — список и удаление.
8. **Inline-кнопки под ответом**: «Подробнее» (развёрнутая версия, отдельным сообщением), «Короче», «Усиленный ответ» (сильная модель, тратит усиленный запрос), «Другой предмет».
9. **Команды**: `/subject`, `/materials`, `/limits` (остаток на сегодня), `/plan` (тариф и оплата), `/ref` (реферальная ссылка), `/help`.

## 5. Предметы

`config/subjects.json` — пресеты: имя, краткое описание, стиль ответа, типичные форматы вопросов, что цитировать (ГК РФ, ФЗ, учебники). Стартовый набор — твои предметы РАНХиГС «Менеджмент», обновляешь раз в семестр и деплоишь. Пользователь при `/subject` видит пресеты и может добавить свой предмет одной строкой (имя + при желании описание) — хранится в БД. Промпт для предмета собирается из описания + первых 500 символов загруженных конспектов (чтобы модель поняла терминологию курса).

## 6. RAG

1. Чанки 600–800 токенов с перекрытием 100, метаданные: user_id, subject_id, файл, страница.
2. Поиск: косинусное сходство в pgvector, top-8, порог 0.35, плюс переранжирование дешёвой моделью, если чанков >4.
3. Лимиты хранения: Free — загрузка недоступна (это главный аргумент за платный тариф); Paid — до 20 файлов, до 150 МБ текста суммарно, файл до 20 МБ.
4. Сканы: PDF без текстового слоя → каждая страница рендерится картинкой → vision-модель извлекает текст. Дорого (~0.3–0.5 ₽ за страницу), поэтому лимит 60 страниц на файл.
5. Изоляция строгая: все запросы к чанкам содержат `user_id`.

## 7. Модели и себестоимость

Цены PolzaAI на 03.09.2026 (за 1M токенов): Claude Sonnet 5 — 230 ₽ вход / 1150 ₽ выход; Gemini 3.5 Flash — 136 ₽ / 814 ₽ (thinking-токены тарифицируются как выход). Дешёвый класс (Gemini 3.1 Flash Lite, GPT-5 mini) — цены нужно снять в кабинете Polza, оценка ~0.5–0.8 ₽ за запрос. Перед стартом обязательно прогнать 20 реальных билетов/задач через 3 кандидата и сравнить качество: для теоретических билетов дешёвой модели хватает, для задач по статистике/экономике нужна сильная.

Профиль запроса: билет текстом — 3 000 токенов вход (промпт, предмет, RAG-чанки, история) + 1 000 выход; задача с фото — 4 600 вход + 1 500 выход.

| Модель | Билет текстом | Задача с фото | Роль |
|---|---|---|---|
| Дешёвый класс (оценка) | ~0.5 ₽ | ~0.8 ₽ | Free-тариф, классификация, обычные запросы Paid |
| Gemini 3.5 Flash | ~1.2 ₽ | ~1.8 ₽ | Запасной вариант |
| Claude Sonnet 5 | ~1.8 ₽ | ~2.8 ₽ (до 4 ₽ с reasoning) | «Усиленный ответ» на Paid |

Embeddings: конспект 50 страниц ≈ 30 000 токенов ≈ 0.4 ₽ на `-large`. Пренебрежимо.

## 8. Тарифы и финмодель

**Free**: 5 запросов/день, но не больше 30 в месяц; дешёвая модель; без загрузки конспектов; фото — можно (это крючок). Месячный кап обязателен: без него бесплатник в сессию стоит до 100 ₽/мес.

**Paid, 199 ₽/мес**: 30 запросов/день, из них до 5 «усиленных» (Sonnet); загрузка конспектов; приоритетная очередь. Мягкий кап 300 запросов/мес — после него только дешёвая модель. Дополнительно на этапе 5 стоит проверить разовый тариф «Сессия, 7 дней — 99 ₽» под пик спроса, но не в первой версии.

**Экономика одного платного пользователя** (ИП на УСН «доходы» 6 %, оплата картой через ЮKassa 2.8 %):

| Статья | ₽ |
|---|---|
| Цена | 199 |
| Комиссия ЮKassa | −5.6 |
| УСН 6 % | −11.9 |
| Чистыми до LLM | 181.5 |
| LLM, лёгкий пользователь (20 запросов: 15 дешёвых + 5 усиленных) | −20 |
| LLM, средний (60: 45 + 15) | −69 |
| LLM, тяжёлый (упирается в лимиты, 300: 250 + 50) | −300 |

Средний пользователь даёт ~112 ₽ маржи (56 %). Тяжёлый убыточен, но их обычно <5 %; лимиты выше подобраны так, чтобы даже тяжёлый не превышал ~1.5 цены подписки. Если реальная доля тяжёлых окажется >10 % — снижаем усиленные до 3/день.

**Free-пользователи — главная статья расходов.** При 30 запросах/мес каждый стоит до 15 ₽, в среднем ~4 ₽. При конверсии 10 % на одного платного приходится 9 бесплатных ≈ 36 ₽ — это ещё треть маржи.

**Сценарии в месяц** (постоянные: VPS 500 ₽, домен ~25 ₽; конверсия 10 %, средний профиль):

| Платных | Выручка | LLM Paid | LLM Free | Комиссии+налог | Хостинг | Чистыми |
|---|---|---|---|---|---|---|
| 10 | 1 990 | 690 | 360 | 175 | 525 | ~240 |
| 50 | 9 950 | 3 450 | 1 800 | 875 | 525 | ~3 300 |
| 200 | 39 800 | 13 800 | 7 200 | 3 500 | 525 | ~14 800 |
| 500 | 99 500 | 34 500 | 18 000 | 8 750 | 1 000 | ~37 000 |

Точка безубыточности — 5–6 платных. Vercel Pro вместо VPS добавляет ~1 900 ₽/мес к постоянным, что сдвигает безубыточность к 20 платным. Стартовый баланс на Polza — 3 000 ₽ хватит на первые 100 пользователей.

Что должно быть в ЮKassa: ИНН ИП, сайт с офертой и политикой конфиденциальности (статическая страница на том же домене), способ фискализации — «Чеки от ЮKassa». Рекуррентные списания: первый платёж с `save_payment_method: true`, потом автосписание раз в 30 дней с уведомлением за 3 дня и кнопкой отмены в `/plan`.

## 9. Риски и что с ними делать

1. **Модерация MAX.** Бот с позиционированием «списывать на парах» рискует не пройти проверку или быть снятым по жалобе. Публичное описание — «учебный ассистент: разбор билетов и задач, подготовка к экзаменам». В промптах нет ничего про списывание, функциональность та же.
2. **Полный сбой в сессию.** Пик нагрузки приходится на 2–3 недели в семестр. Polza может отдавать 429 — нужен фолбэк на вторую модель того же класса и очередь с честным сообщением «отвечу через минуту».
3. **ПДн (152-ФЗ).** Храним MAX user_id, имя, загруженные тексты конспектов. Нужны политика конфиденциальности, согласие при `/start`, удаление по команде `/delete_me`. Сервер на Timeweb закрывает вопрос локализации; Supabase (серверы вне РФ) допустим только для демо без реальных пользователей.
4. **Дубли и потерянные события.** Дедупликация по `update_id`, идемпотентность отправки, логирование каждого входящего события.
5. **Курс рубля в ценах Polza.** Цены привязаны к доллару; закладывай буфер 20 % и пересматривай лимиты раз в квартал.
6. **Стоимость сканов.** OCR через vision — самая дорогая операция; лимит 60 страниц и предупреждение до загрузки.

## 10. Этапы

**Этап 0 — подготовка (1–2 дня).** Получить токен бота в MAX, ключ Polza с балансом, проект Supabase, каркас репо с деплоем «hello» на Vercel и подписанным webhook. Выход: бот отвечает «пинг».

**Этап 1 — MVP ответов (неделя).** Текст и фото → классификация → структурированный ответ по билету/задаче → разбиение на сообщения, кнопки «Подробнее/Короче». Пресеты предметов из репо, выбор предмета. Дедупликация. Ты гоняешь на своих билетах и правишь `docs/PROMPTS.md`. Выход: бот пригоден для личного использования.

**Этап 2 — файлы и personal RAG (неделя).** Парсинг PDF/DOCX/XLSX, сканы через vision, индексация в pgvector, `/materials`, ответы с опорой на конспект. Пользовательские предметы.

**Этап 3 — лимиты и рост (3–5 дней).** Таблица пользователей, дневные и месячные лимиты, `/limits`, реферальная ссылка (+10 запросов за друга), админ-команда со статистикой (пользователи, запросы, расход ₽ по моделям). Раздача 20–30 одногруппникам, сбор обратной связи. Всё ещё на Vercel Hobby — платежей нет, нарушения нет.

**Этап 4 — монетизация (неделя).** Переезд на Timeweb (Docker Compose: приложение + Postgres с pgvector, Caddy для HTTPS) или Vercel Pro. Лендинг с офертой и политикой, договор с ЮKassa, платёжный webhook, рекуррентные списания, `/plan`. Согласие на ПДн, `/delete_me`. Выход: первые платные подписки.

**Этап 5 — масштабирование (по ситуации).** Сессионный тариф, рассылка «через 2 дня экзамен» по расписанию предметов, тесты качества на выборке билетов, публикация бота в каталоге MAX, контент под рилсы (сценарии «показал фото билета — получил ответ»).

Первые четыре этапа — около месяца работы в паре с Claude Code при твоей загрузке в 2–3 часа в день.

## 11. Что нужно от тебя перед этапом 0

1. Токен бота MAX (создать бота в бизнес-кабинете, сохранить в `.env`).
2. Ключ PolzaAI и стартовый баланс; заодно снять цены дешёвого класса моделей.
3. Аккаунт Supabase (демо) — или сразу доступ к VPS, если решишь стартовать там.
4. Список предметов на текущий семестр с одной строкой описания каждого — заполню `config/subjects.json`.
5. 10–15 реальных билетов и 5 задач с фото — тестовый набор для промптов и сравнения моделей.
