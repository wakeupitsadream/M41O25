# План разработки: приложение группы М41О25

Основано на брифе (BRIEF.md, ответы на 63 вопроса из QUESTIONS.md). Актуальные данные (Vercel/РФ, PolzaAI, бесплатные тиры) проверены поиском 02.09.2026. Все спорные места прогнаны через адверсариальную проверку — противоречия ниже уже разрешены.

## 0. Что строим — в одном абзаце

Тёмная PWA (сайт, устанавливаемый на экран «Домой» iPhone) для 21 одногруппника: расписание с еженедельным распознаванием скана учебного отдела и офлайн-кешем, домашка «за 20 секунд» с вложениями и вики-правками, новости, задачи с чек-листом «кто сдал», опросы, контакты, дни рождения, анонимные вопросы. Хостинг Vercel (0 ₽), БД Neon (0 ₽), файлы Cloudflare R2 (0 ₽), распознавание PolzaAI (~15–30 ₽/мес, бюджет 100–200 ₽). Одна платная зависимость на весь проект.

## 1. Ключевые решения (сводка)

| Вопрос | Решение |
|---|---|
| Платформа | PWA на Next.js, mobile-first, тёмная тема — единственная в v1 |
| Домен | **Остаёмся на `имя.vercel.app`**: по ресёрчу (репорты окт 2025 – фев 2026) vercel.app из РФ работает без VPN, а IP кастомных доменов Vercel периодически блокирует РКН. Свой .ru — позже и только как алиас |
| БД | **Neon**, не Supabase: Supabase на каникулах засыпает через 7 дней и требует ручного resume; Neon просыпается сам (<1 с) |
| Файлы | **Cloudflare R2** (10 ГБ, egress 0 ₽), но клиент НИКОГДА не ходит в Cloudflare напрямую (из РФ нестабильно) — всё через прокси-роуты на vercel.app. Фолбэк, если R2 не заведётся из РФ без карты: Vercel Blob 1 ГБ, тот же прокси-паттерн |
| OCR | PolzaAI, модель `google/gemini-3.5-flash` (~2–3 ₽/прогон), эскалация кнопкой на `anthropic/claude-sonnet-5` (~5–8 ₽). Ключ, base_url и модель — в env |
| Вход | Единый инвайт-код + «выбери себя из списка 21» + opaque-токен устройства в httpOnly-cookie на 12 мес. Без паролей, email и сторонних auth |
| Роли | Админ (Максим) / модератор (староста) / студент |
| Уведомления | Никаких пушей. Внутри приложения — лента «Что нового» + точки на табах |
| Часовой пояс | Константа приложения `Asia/Yekaterinburg` (+05). Все даты пар и дедлайнов — в местном времени, все сравнения `now()` — через неё |
| Срок | **16–18 недель — базовый план** (14 — если повезёт). Запуск «когда готово», наполненным |

## 2. Архитектура и инфраструктура

### Стек

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | Next.js 15 (App Router) + React 19 + TypeScript | UI, API-роуты и cron в одном репо; нативно для Vercel |
| Стили | Tailwind CSS 4 | тёмная тема дизайн-токенами, ноль рантайм-CSS |
| Анимации | Motion (Framer Motion): `layoutId` + `AnimatePresence` | shared layout transitions — ровно «погружение» семестр→неделя→день |
| БД | Neon Postgres free, драйвер `@neondatabase/serverless` | scale-to-zero, автопробуждение, 0.5 ГБ хватит на годы |
| ORM | Drizzle + drizzle-kit | быстрый cold start, SQL-миграции в git |
| Файлы | R2 через `@aws-sdk/client-s3`, server-side only | 10 ГБ, egress 0 |
| PWA | Serwist | актуальный service worker для App Router |
| Vision | OpenAI SDK → `base_url: https://polza.ai/api/v1` | оплата рублями/СБП, structured output, `/api/v1/balance` для админки |
| Валидация | Zod | одна схема на форму, action и ответ vision-модели |

### Схема

```
iPhone (Safari / установленная PWA)
   │ HTTPS — только *.vercel.app
   ▼
Next.js на Vercel Hobby: RSC-страницы + API-роуты + 1 cron
   │                 │                  │
   ▼                 ▼                  ▼
Neon Postgres    Cloudflare R2      PolzaAI (vision)
(все данные,     (вложения, сканы,  (только server-side,
 group_id везде)  бэкапы) — только   1 запрос в неделю)
                  server-side S3
```

### PWA и офлайн (разрешение главного риска)

Расписание — единственный раздел с офлайн-требованием, поэтому оно **не RSC, а клиентский компонент**, который читает выделенный JSON-эндпоинт `GET /api/schedule/current` (текущая + следующая опубликованные недели). Service worker кеширует:

- app shell и статику — precache/CacheFirst;
- `GET /api/schedule/current` — **NetworkFirst с таймаутом ~3 с** и фолбэком в кеш: в универе при плохой связи расписание открывается мгновенно из кеша, с плашкой «Офлайн · данные от сб 12:40»;
- остальные разделы (RSC) офлайн честно показывают заглушку «нет сети».

iOS-нюансы: `apple-touch-icon` 180px (iOS игнорирует manifest-иконки), свой экран-подсказка «Поделиться → На экран "Домой"» (`beforeinstallprompt` в Safari нет), `viewport-fit=cover` + safe-area, `100dvh`. **У установленной PWA отдельное хранилище от Safari** → онбординг ведёт в порядке «сначала установи, потом войди» (экран входа детектит standalone-режим; в Safari до входа показываем шаг установки, вход в браузере тоже работает — просто попросит код второй раз внутри PWA). httpOnly-cookie не подпадает под 7-дневную чистку ITP — привязка живёт семестрами. При `visibilitychange` — refetch данных (iOS держит PWA замороженной сутками, без этого экран «вчерашний»).

### Деплой, миграции, бэкапы

- GitHub → Vercel: push в `main` = прод, PR = preview.
- Миграции: `drizzle-kit migrate` **только при `VERCEL_ENV === 'production'`** — иначе preview-деплой из ветки применит черновую миграцию к прод-базе.
- **Один** cron-роут `/api/cron/daily` (Hobby: 2 крона максимум, точность «в течение часа» — для нас ок): JSON-дамп всех таблиц → `backups/YYYY-MM-DD.json.gz` в R2 (храним 30 шт.) + автоудаление сканов расписания старше 30 дней. Файлы-вложения не бэкапим — риск принят («потеря неприятна, не катастрофа»). Восстановление — `scripts/restore.ts`, проверить один раз до запуска.
- Транзакции: Neon HTTP-драйвер не поддерживает интерактивные транзакции — не полагаемся на них; запись в ленту `activity` идёт вторым запросом после сущности, потеря отдельной строки ленты некритична.

### Env

`DATABASE_URL`, `R2_*`, `POLZA_API_KEY`, `OCR_MODEL`, `OCR_MODEL_STRONG`, `AUTH_SECRET`, `ANON_PEPPER`, `CRON_SECRET`, `APP_TZ=Asia/Yekaterinburg`. Инвайт-код — НЕ в env, а в `groups.invite_code` (ротация кнопкой без redeploy).

### Чего сознательно нет в v1

Websockets/realtime и чат; пуши; Sentry и мониторинг-сервисы (вместо них админ-сводка + логи Vercel); мульти-тенант (но `group_id` в каждой таблице); n8n, очереди, Redis, отдельный бэкенд.

## 3. Модель данных

Принципы: каждая пара привязана к **конкретной дате** (не «день недели × чётность») — сканы приходят на конкретную неделю, и этот же формат без доработок покрывает сессию «пары по датам». «Архив» — вычисляемое состояние (`due_date < now()`), ноль фоновых задач. Мягкое удаление (`deleted_at`) для контента.

- **groups** — задел: `id, name, invite_code`.
- **users** — 21 студент, внесены заранее: `full_name, nickname, avatar_emoji, color` (личный цвет из палитры 8 — назначается при заведении, без коллизий), `role, birthday, show_hw_done, status('active'|'removed'), last_seen_at, feed_seen_at`. `feed_seen_at` — отдельно: обновляется только при открытии «Что нового», иначе лента «прочитывается» раньше времени.
- **device_sessions** — `user_id, token_hash(sha256), user_agent, created_at, last_used_at, revoked_at`. Opaque-токен 256 бит, клиенту — httpOnly+Secure cookie на 12 мес со скользящим продлением; отзывается из админки.
- **semesters** — `title, starts_at, ends_at`. Архив семестра = **только расписание read-only** (сетка недель); архив ДЗ живёт в разделе ДЗ.
- **weeks** — `semester_id, starts_on, parity('upper'|'lower'|null), status('draft'|'published'), published_at`.
- **lessons** — `week_id, subject_id, date, slot, starts_at, ends_at, room, teacher_name, kind('lecture'|'practice'|'lab'|'exam'|'credit'|'other'), note, is_cancelled, modified_after_publish`. Скан приходит на неделю известной чётности → пары «чужой» чётности при сохранении черновика **отбрасываются**; переключатель верх/низ/обе существует только на экране проверки черновика.
- **schedule_imports** — `week_id, scan_file_key, model, raw_llm_json, status`. Хранит исходник — можно перераспознать сильной моделью и сравнить.
- **subjects** — справочник: `name, short_name, color, default_teacher, default_room, archived`.
- **homework** — `subject_id?, lesson_id?, title?, body (текст автора), due_date, duplicate_of_id?, created_by, ...`. Дедлайн ставится всегда: по умолчанию «следующая пара предмета» из расписания; если предмет не указан — авто-архив через 14 дней от создания. Архив = `due_date < now()` (в APP_TZ).
- **hw_edits** — вики-правки как **append-only блоки** (упрощение после критики: никаких диффов/сегментов): `homework_id, author_id, text, created_at`. Каждая правка — отдельный блок под оригиналом с маркером автора. Правка/удаление оригинала — автор и админ.
- **hw_done** — личные галочки: PK `(user_id, homework_id)`.
- **attachments** — полиморфно для ДЗ/новостей/задач: `entity_type, entity_id, file_key, file_name, mime, size_bytes, uploaded_by`.
- **news** — `author_id, title?, body, pinned_at?`.
- **tasks** — `title, description?, due_date?`; **task_checks** — «кто сдал»: PK `(task_id, user_id)`, `checked_by, checked_at`.
- **polls / poll_options / poll_votes** — `is_anonymous` скрывает имена голосовавших **в UI** (в БД голос хранится с user_id — иначе не удержать «один голос»); эта псевдонимность честно оговаривается в интерфейсе создания опроса.
- **contacts** — `kind('teacher'|'dean'|'other'), name, subject_or_role, phone?, email?, messenger?, note?`.
- **anon_questions** — `body, answer_body?, answered_by?, created_at`. **Колонки автора нет вообще** — ни в строке, ни в логах; время публикации округляется до часа. Антиспам — отдельная таблица **anon_quota**: ключ `HMAC-SHA256(user_id, ANON_PEPPER)` + суточный счётчик (лимит 5/сутки); связи «счётчик ↔ текст вопроса» нет. Честная оговорка: абсолютной анонимности от владельца сервера не существует — гарантия архитектурная (код в принципе не пишет автора), репозиторий можно показать группе.
- **comments** — только к домашке (см. §6, открытый вопрос 24): `homework_id, author_id, body`.
- **reactions** — эмодзи-реакции к новостям/ДЗ/задачам: PK `(entity_type, entity_id, user_id, emoji)`.
- **activity** — лента «Что нового»: `event_type, entity_type, entity_id, actor_id?, created_at`.

API: чтение — RSC + прямые Drizzle-запросы (кроме расписания — JSON-эндпоинт для офлайна); мутации — Server Actions с `requireUser()/requireModerator()/requireAdmin()` + Zod. Route handlers только для: `/api/files/[id]` (прокси-стрим из R2), `/api/upload`, `/api/admin/recognize`, `/api/schedule/current`, `/api/cron/daily`.

**Rate limit** (ответ на вопрос 40): единый — **15 создающих действий в час** на пользователя (ДЗ, правки, комментарии, опросы), счётчик прямо в Postgres по индексу `(author_id, created_at)`, без Redis; анонимные вопросы — 5/сутки через anon_quota. Админ и модератор без лимита. Для 21 знакомого человека этого достаточно: почти весь контент подписан, социальное сдерживание сильнее лимита.

## 4. Пайплайн расписания (OCR)

Субботний ритуал админа, ~10–15 минут с телефона:

1. **Загрузка.** Админка → «Новая неделя» (даты и чётность проставляются сами по предыдущей неделе). 1–3 фото скана; `accept="image/jpeg,image/png"` (Safari сам транскодирует HEIC), клиент сжимает до ~2500px JPEG (`browser-image-compression`). **Каждое фото загружается отдельным запросом** в R2 (лимит тела 4.5 МБ), роут распознавания получает ключи R2, не тела.
2. **Распознавание.** `/api/admin/recognize`: OpenAI SDK → PolzaAI, модель из `OCR_MODEL`, `detail: high`, `response_format: json_schema` + плагин `response-healing`, **плюс обязательная Zod-валидация ответа с одним ретраем** (json_schema через агрегатор не всегда строгий). Ответ 10–30 с — влезает в лимит Hobby даже в 60 с (`maxDuration: 300` заявляем, но не полагаемся — проверка в этапе 0). Три неудачи → баннер «внести вручную».
3. **Проверка.** Черновик рендерится той же сеткой недели, что видят студенты. Тап по паре → шторка: предмет (автокомплит по справочнику), преподаватель, кабинет, время, верх/низ/обе. Клетки `uncertain: true` подсвечены жёлтым, рядом `raw_text` — что реально было в ячейке.
4. **Публикация.** `draft → published`; при сохранении пары «чужой» чётности отброшены, дни превращены в даты.

Кнопка «Распознать сильной моделью» (`OCR_MODEL_STRONG`) перезаписывает только черновик. **Полностью ручной ввод — тот же экран черновика с пустой сеткой**: OCR лишь предзаполняет; отказ PolzaAI никогда не блокирует выпуск расписания. Замены в день занятий — точечная правка опубликованной недели: пара получает `modified_after_publish` (бейдж «изменение» до конца дня), отмена — `is_cancelled` (зачёркнута, не удалена).

JSON-схема ответа: `{group, week_type, confidence_notes, lessons: [{day, slot, time_start, time_end, subject, lesson_type, teacher, room, week_type: upper|lower|both, uncertain, raw_text}]}`.

Промпт (каркас): «На изображениях — расписание НЕСКОЛЬКИХ групп. Извлеки ТОЛЬКО группу „М41О25“ (варианты написания: М41О25, М-41-О-25). Преподаватель и кабинет — отдельные поля. Дробь/пометки „верх/низ“ → week_type upper/lower, обычная ячейка → both. Потоковая ячейка на несколько групп относится и к М41О25. Пустая ячейка = пары нет, не выдумывай. Не разобрал — uncertain: true + raw_text буквально. Ответ — строго JSON по схеме.»

Стоимость: Gemini 3.5 Flash ≈ 2–3 ₽/прогон, Sonnet 5 ≈ 5–8 ₽ → реально ~15–30 ₽/мес, бюджет 100–200 ₽/мес. Минимального пополнения PolzaAI (100 ₽, карта РФ/СБП) хватает на месяцы. Остаток баланса — в админ-сводке через `/api/v1/balance`.

Скан — внутренний документ вуза: наружу не публикуется никогда, в приложение попадает только распознанный текст пар М41О25, данные чужих групп не сохраняются, файл скана виден только админу и автоудаляется через 30 дней.

## 5. UX, экраны, дизайн

**Таб-бар (5):** `Расписание · ДЗ · [+] · Группа · Профиль`. Центральная приподнятая кнопка `+` — форма «ДЗ за 20 секунд» из любого места. Точки непрочитанного на табах — от `feed_seen_at`.

| Экран | Суть |
|---|---|
| **Неделя** (первый экран) | 6 карточек дней; бейдж чётности; свайп ←→ между неделями; сегодняшний день крупнее, с акцентной рамкой и живым прогрессом «3-я пара из 4» |
| **День** | таймлайн пар (время, предмет, преподаватель, кабинет) + прикреплённые ДЗ |
| **Семестр** | сетка недель-плиток + счётчики («до сессии 47 дней», «семестр пройден на 62%»); вход — кнопка «наверх» (pinch-out — прогрессивное улучшение, не основной вход) |
| **ДЗ** | лента по дедлайну, фильтр по предмету, архив; карточка с вложениями, правками, комментариями |
| **Группа** (хаб) | Новости · Задачи · Опросы · Анонимные вопросы · Контакты · Дни рождения |
| **Что нового** | лента событий с `feed_seen_at`; колокольчик в шапке |
| **Профиль** | ник, скрытая галочка «сделал» (пасхалка), выход. Настройки «темы-акцента» НЕТ — акцент один |
| **Админка** | скан→черновик→публикация; замены; юзеры и сессии; предметы; семестры; контакты; сводка (баланс Polza, дата бэкапа, размер БД) |

**Навигация «в глубину»** — только внутри «Расписания»: семестр → неделя → день, Motion `layoutId`-морф карточки в шапку + уход предыдущего уровня вглубь (`scale 0.94, blur`). Реализация — один роут с внутренним состоянием уровня + `history.pushState` (`/s/2026-09-07/mon`), потому что exit-анимации между роутами App Router капризны. **План Б с таймбоксом** (риск pushState/popstate-конфликтов с Next): обычные роуты + упрощённые анимации — решение в конце этапа 1, не позже. Остальные разделы — плоские переходы. На вложенных экранах всегда явный back-элемент (edge-свайп в standalone-PWA ненадёжен).

**Дизайн:** глубокий холодный тёмный фон + один кислотный акцент + крупная типографика + умеренное стекло (blur только на таб-баре и шапке). Референсы: Linear/Vercel (дисциплина), Cash App/Spotify Wrapped (лайм на тёмном, смелые цифры), Apple Fitness (глубина слоёв). Палитра: фон `#0A0A0E`, поверхности `#141419`/`#1C1C24`, бордер `#26262F`, текст `#F4F4F6`/`#9C9CA8`, **акцент лайм `#C8FF2E`** (только: текущий день/пара, кнопка `+`, активный таб, CTA), семантика `#4ADE80`/`#FB7185`/`#FBBF24` точками. Шрифты через `next/font` (self-host, ноль запросов к Google из РФ): заголовки и цифры — **Unbounded** (variable, кириллица, OFL), текст — **Inter Variable**. Проверить tabular figures у Unbounded; нет — время набираем Inter'ом.

**Форма «ДЗ за 20 секунд»:** bottom-sheet, одно поле с автофокусом + чип предмета, предзаполненный текущей (±20 мин) парой из расписания, дедлайн по умолчанию — следующая пара предмета («к чт 11.09»). «Отправить» / «Оформить подробнее». Три действия от `+` до готово.

**Вики-правки без винегрета:** цвет не на буквах, а на структуре — каждая правка отдельный блок: левая линия 3px цвета автора + мини-аватар + текст обычным белым на подложке цвета автора с альфой ~8%. Цвета — 8 пастельно-ярких из `users.color`, тот же цвет у аватара везде (комменты, «кто сдал») — бесплатная система идентичности.

**Отметка «дубль»:** любой студент через меню карточки ДЗ; дубль сворачивается и линкуется на оригинал; снимает автор отметки или админ.

**Пустые состояния:** 1 эмодзи + 1 строка с характером + действие («ДЗ нет 🎉 Живём»). Каникулы — полноэкранное «Каникулы до 09.02 ❄️» с отсчётом. Нет скана — «Расписания пока нет. Обычно появляется в субботу вечером».

## 6. Доступ, роли, безопасность

**Вход:** инвайт-код группы (одно сообщение в беседу ВК) → список 21 фамилии → «выбери себя» → опциональный ник → внутри. Захват чужого профиля — «профиль занят, напиши админу», админ кнопкой сбрасывает привязку. Ротация кода — кнопка в админке (мгновенно, сессии живут). Отчисленный: `status='removed'` + сессии убиты, записи остаются. Посторонним — только экран «Нет доступа» без названия группы и вуза, `robots: noindex` на всём.

**Права:**

| Раздел | Студент | Модератор (староста) | Админ |
|---|---|---|---|
| Расписание | смотрит | смотрит | всё: скан, правка, публикация, замены |
| Домашка | создаёт, правит (блоками с маркером), «дубль», комменты | = студент | + удаление любого, откат |
| Новости | смотрит, реагирует | постит, закрепляет | + удаление |
| Задачи | смотрит | создаёт | + отметки «сдал» — только админ |
| Опросы | **создаёт**, голосует | + закрыть опрос | + удаление |
| Контакты, ДР | смотрит | предлагает правки | правит |
| Аноним. вопросы | задаёт | отвечает | + удаление |
| Предметы, семестры, юзеры | — | — | правит |

Проверка роли — на сервере в каждой мутации, не только в UI. Банов нет: модерация = право удаления + rate limit.

**Приватность:** минимум данных — имя/ник, опциональный ДР (можно без года), эмодзи-аватар. Никаких телефонов/email студентов. Контакты преподавателей — только то, что они сами дали студентам. Название приложения нейтральное, без символики РАНХиГС.

## 8. Роадмап

Ресурс: 5–7 ч/нед по худшей неделе, до 14 ч в хорошие; час — это час Максима на постановку задач Claude Code, ревью и проверку на реальном iPhone. **Базовый план — 16–18 недель**; 14 — если этапы 1 и 6 не съедят буфер (дизайн с вау-эффектом обычно съедает). Каждый этап закрывается критерием «можно потыкать».

| Этап | Недели | Содержимое | Готово = |
|---|---|---|---|
| **0. Фундамент** | 1 | репо, Next+TS+Tailwind, деплой на vercel.app, Neon+Drizzle, вход (код→выбор себя→токен), «нет доступа», PWA-манифест. **Плюс проверки рисков: R2 регистрируется/работает из РФ (иначе фолбэк Vercel Blob), polza.ai отвечает с серверов Vercel, maxDuration на Hobby** | ставится на iPhone, пускает по коду |
| **1. Дизайн-система** | 2–3 (риск +1) | палитра, типографика, компоненты, таб-бар и главное — анимация «погружения» на мок-данных до «вау» на устройстве. В конце этапа — решение по плану Б навигации | «проваливание» день↔неделя↔семестр хочется показывать |

## 9. Риски

| Риск | Митигация |
|---|---|
| РКН заблокирует vercel.app | форс-мажор вне контроля; миграция = любой хостинг с Node, БД и файлы не привязаны к Vercel |
| R2 не зарегистрировать из РФ (нужна карта) | проверка в этапе 0; фолбэк Vercel Blob 1 ГБ, тот же прокси-паттерн |
| polza.ai недоступен/закрылся | OpenAI-совместимый API: миграция на AITunnel/ProxyAPI = смена 2 env-переменных; ручной ввод всегда работает |
| pushState-навигация конфликтует с App Router | таймбокс в этапе 1, план Б: обычные роуты + упрощённые анимации |
| Формат скана изменится (новый шаблон деканата) | промпт + Zod-схема в одном файле, правится за вечер; фолбэк ручной ввод |
| Никто не постит ДЗ | форма за 20 секунд + Максим и староста сеют первые 2 недели + карточки-шаринг тянут остальных |
| Vercel Hobby «non-commercial» | студенческий проект группы соответствует |

## 10. Стоимость итого
