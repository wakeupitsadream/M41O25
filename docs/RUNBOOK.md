# Runbook: «упало в 8:20»

Один оператор, телефон в руке, первая пара через 10 минут. Порядок действий, без размышлений.

## 1. Что именно не работает (2 минуты)

1. Открой `https://raspison.vercel.app/enter` в Safari (не в приложении). Открылось — сервер жив, проблема в данных или у конкретного человека. Не открылось или ошибка Vercel — шаг 3.
2. Открой приложение сам. Расписание показывается с плашкой «Офлайн · данные от …» — значит, приложение не достучалось до сервера или базы, но у людей всё равно есть кеш расписания. Можно писать в беседу: «расписание в приложении актуально, остальное чиним».
3. Vercel → проект raspison → Deployments. Последний production-деплой красный (Error) — упала сборка, live остаётся предыдущий деплой, пользователи этого не видят. Зелёный, но сайт не отвечает — смотри Logs (Runtime) и `Observability → Errors`.

## 2. Быстрые лекарства

- **Сломал последний деплой.** Deployments → предыдущий зелёный production → «⋯» → Instant Rollback. Секунды, без пересборки. Работает, когда production-деплоев больше одного.
- **База не отвечает** (`connect ECONNREFUSED`, `timeout`, «too many connections»). Neon → Project → Compute: статус, лимит compute-часов (Free — кончается в конце месяца при постоянной нагрузке). Suspended из-за лимита — включить, при повторении перейти на платный план или снизить нагрузку (см. ROADMAP 2.20). Neon Status: status.neon.tech.
- **Vercel сам** (status.vercel.com). Ждать. Написать группе, что расписание у них в приложении есть.
- **Никто не может войти, «Такого кода нет».** Админка → Настройки: проверь код. Люди набирают его русской раскладкой — с этим приложение справляется, но код из закрепа должен быть свежим.
- **Человек заблокирован** («Слишком много попыток»). Блокировка профиля снимается сама через 1/5/30 минут или сутки; админ может сбросить PIN в Админка → Люди.
- **Пропали пары на неделю.** Админка → Расписание: неделя в статусе черновик — опубликовать. Нет недели — Новая неделя → скопировать прошлую той же чётности → поправить → опубликовать.
- **Вложения не открываются, бэкапа нет.** Vercel → Settings → Environment Variables: есть ли `R2_*`; Cloudflare R2 → токен не отозван. После правки переменных нужен Redeploy.
- **Распознавание не работает.** Заполни неделю вручную (10 минут), разбор потом: Админка показывает баланс Polza и ошибку последнего прогона.

## 3. Восстановление из бэкапа (крайний случай)

Бэкапы: R2 → бакет → `backups/YYYY-MM-DD.json.gz` (30 последних) или скачанный вручную из Админки. Восстановление с ноутбука:

```bash
DATABASE_URL=<новая или очищенная база Neon> npm run db:migrate
DATABASE_URL=... npm run db:restore -- ~/Downloads/raspison-2026-09-03.json.gz --truncate
```

Скрипт печатает новый инвайт-код: в дампе нет PIN-ов, все профили свободны — войди первым, задай PIN, потом кидай код группе. Файлы-вложения в бэкап не входят.

## 4. Что написать группе

Коротко и сразу, не ждать починки: «Приложение прилегло, расписание на сегодня: <текст или фото>. Чиню, напишу, когда заработает». Через час — статус. Молчание хуже любой ошибки.

## 5. Контакты и доступы

Vercel и Neon — вход через GitHub-аккаунт wakeupitsadream; Cloudflare и Polza — отдельные логины. Держи их в менеджере паролей на телефоне. Второй админ в приложении (староста) должен быть назначен заранее: Админка → Люди → роль.
