# Запуск на группу: порядок действий

Дата: 07.09.2026. Составлено по аудиту готовности (42 подтверждённых пункта, пять независимых линз с проверкой каждой находки по коду).

Приложение развёрнуто и работает: `raspison.vercel.app`, код из `main`, миграции применяются автоматически при сборке. Ниже — то, без чего группа не может начать пользоваться, в том порядке, в котором это надо делать. Порядок не косметический: часть шагов ломается, если сделать их после рассылки кода.

## Почему именно такой порядок

Пока в базе демо-люди, экран «Кто ты?» показывает выдуманные фамилии, и человек не находит себя. Пока не сменён инвайт-код, список из 21 фамилии открыт любому, кто угадает `M41-O2025` (код напечатан в логе сборки Vercel). Пока нет R2, не работают фото к домашке, загрузка скана расписания и ежедневный бэкап — три разные вещи, выключенные одной незаполненной переменной. Поэтому сначала гигиена и данные, и только потом сообщение в беседу.

## Шаг 1. Гигиена доступа (15 минут, до всего остального)

1. Админка → Настройки → «Сменить код». Новый код записать себе, в беседу пока не отправлять.
2. Vercel → Settings → Environment Variables: удалить `SEED_ADMIN_NAME` и `SEED_INVITE_CODE`. Группа и админ уже созданы, переменные больше не нужны и хранят старый код.
3. Там же: `DATABASE_URL` и секреты оставить только для Production, из Preview убрать. Иначе preview любой ветки читает и пишет боевую базу.
4. Cloudflare R2: создать бакет, токен, заполнить четыре переменные `R2_*`, сделать Redeploy. Проверить в админке карточку «Диагностика»: хранилище должно перестать быть локальным.

## Шаг 2. Проверить и вычистить демо-данные (15–25 минут)

Признак, что демо-прогон был: на `/admin` плитка «Люди» показывает около 21 при том, что реальных ты не заводил, «Предметы» — 8, и есть опубликованные недели с парами вроде «Матан», «Микро», «Физра». Косвенно это подтверждается семестром «Осень 2026», у которого сессия начинается 28.12 при конце семестра 27.12 — такую пару дат создаёт только сид с `--demo`.

Чистить в этом порядке:

1. Недели: `/admin/schedule` → каждую демо-неделю → «Удалить». Пары уходят каскадом. Это важно сделать первым: на группу (группа, понедельник) стоит уникальный индекс, и реальная неделя ляжет поверх демо-недели, если её не убрать.
2. Люди: `/admin/users` → карточка → «Удалить из группы». Профиль получает статус `removed` и пропадает из списка входа, состава, счётчиков и дней рождения. SQL не нужен.
3. Предметы: `/admin/subjects` → карточка → «В архив». Удаления в интерфейсе нет и оно не требуется: архивные не попадают ни в выбор предмета в домашке, ни в редактор пары, ни в справочник для распознавания скана.
4. Семестр: `/admin/semesters` → «Осень 2026» → поле «Сессия с» на дату внутри семестра (например, 14.12). Иначе фаза «Сессия» не покажется никогда. В новых семестрах это поле теперь валидируется.

## Шаг 3. Наполнить боевые данные (1,5–2 часа)

1. Люди: 21 человек. Список фамилий сверить буква в букву со старостиным — сам себя добавить человек не может по замыслу, а опечатку правит только админ. Быстрый путь — «Добавить списком» на `/admin/users`: вставить список из беседы, посмотреть предпросмотр, подтвердить.
2. Предметы: реальный справочник семестра. Заполнить преподавателя и аудиторию по умолчанию — они подставляются в распознанный скан и экономят правки каждую субботу.
3. Время пар: Админка → Настройки → сетка звонков вуза. Сидовские значения почти наверняка не совпадают с реальными.
4. Расписание: опубликовать текущую и следующую неделю. Без опубликованной недели главный экран пустой.
5. Контакты преподавателей и дни рождения — по мере появления, не блокирует запуск.

## Шаг 4. Второй админ и сторож (10 минут)

1. `/admin/users` → староста → роль `admin`. Один админ — это точка отказа: забытый PIN и потерянный телефон лечит только админ, а расписание в субботу должен кто-то опубликовать, даже если ты в отъезде.
2. healthchecks.io: завести бесплатный чек с периодом «раз в сутки», ссылку положить в переменную `HEALTHCHECK_URL`. Тогда молчание cron (не ушёл бэкап, упала база) превращается в письмо, а не в тишину до момента, когда бэкап понадобится.

## Шаг 5. Проверка на живом iPhone (1–1,5 часа)

Пройти `docs/DEVICE-CHECKLIST.md` на двух телефонах. Всё, что проверено до сих пор, снято в headless Chromium — WebKit приложение не видел ни разу. Особое внимание: установка на домашний экран, вход в установленном приложении, ночь в фоне и утреннее открытие, авиарежим на паре, шторка с клавиатурой, фото и PDF, шаринг дня.

## Шаг 6. Ключ PolzaAI и первая суббота (30 минут + первый реальный прогон)

1. Ключ Polza, пополнение, сверка id моделей с каталогом `polza.ai/models` → `OCR_MODEL`, `OCR_MODEL_STRONG`. Неверный id даёт непонятную 404.
2. Первую субботу закладывать вдвое больше времени: распознавание ни разу не работало на настоящем документе. Ручной ввод недели остаётся запасным путём и занимает 40–60 минут.
3. Три реальных скана с ожидаемыми парами в `fixtures/ocr/` дадут измеримую точность через `npm run ocr:eval` — после этого промпт можно править не вслепую.

## Шаг 7. Сообщение в беседу и первые две недели

Одно сообщение: ссылка, новый код латиницей, «сначала установить на домашний экран, потом войти». Дальше две недели приложение придётся заселять руками: первая новость, первый опрос, домашка каждый день. Пуш-уведомлений в проекте нет по замыслу, поэтому привычка держится на том, что в приложении каждый день есть что-то новое, и на коротком напоминании в беседе. Без этого люди открывают приложение раз в неделю.

## Что пока не сделано в коде и когда это понадобится

Подгруппы в расписании: скан на две подгруппы даёт пары-двойники, помеченные как сомнительные, и их надо разводить руками каждую субботу. Понадобится, если у группы реально есть деление на подгруппы — решать после первого настоящего скана.

Канал «пару отменили»: сейчас об отмене узнают, только открыв приложение. Веб-пуш на iOS требует установленной PWA и отдельной работы; дешёвая замена — кнопка «Скопировать текст для беседы» у отменённой пары.

Playwright Test с ролями (студент, староста, админ) вместо скриптов-сценариев: страховка от регрессий, когда правок станет больше.
